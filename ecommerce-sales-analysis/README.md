# E-commerce Sales Analysis

## Overview

This project analyzes sales data from the Brazilian Olist marketplace using SQL and Python/Pandas.

The goal is to understand how sales perform over time, which categories and products generate the most value, and how customers behave after making a purchase.

The project also includes data cleaning and validation steps to make sure the analysis is reliable.

## Business Questions

- How much revenue was generated by delivered orders?
- How do sales and order volume change over time?
- Which categories and products generate the most value?
- How concentrated are sales across categories and customers?
- How many customers buy only once, and how many buy more than once?
- Which data quality issues affect the analysis?

## Dataset

The analysis uses selected tables from the [Brazilian E-Commerce Public Dataset by Olist](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce).

Tables used:

- `orders`
- `order_items`
- `products`
- `customers`
- `product_category_name_translation`

Main relationship used:

```text
customers -> orders -> order_items -> products -> product_category_name_translation
```

## Analytical Approach

The project is divided into two parts:

- SQL is used for data cleaning, joins, KPI calculations, and trend analysis.
- Pandas is used for data checks, exploratory analysis, and visualizations.

Only delivered orders are included in revenue metrics because canceled or unavailable orders do not represent completed sales.

For this project:

```text
product_revenue = price
freight_revenue = freight_value
gross_order_value = price + freight_value
```

This separation helps show product sales and delivery charges clearly.

## Key Metrics

- Delivered orders: `96,478`
- Gross order value: `15,419,773.75`
- Product revenue: `13,221,498.11`
- Freight revenue: `2,198,275.64`
- Average gross order value per order: `159.83`
- Repeat customer share: `3.0%`

## Key Findings

- Delivered orders generated `15,419,773.75` in total gross order value.
- Sales are concentrated in a small number of categories. The top 10 categories represent `62.38%` of total gross order value.
- Most customers buy only once. `97.0%` of customers placed one delivered order, while only `3.0%` placed more than one.
- Customer spending is uneven: a small number of customers account for much higher spend than the rest.
- Some product records have missing category information, but those transactions were kept in the analysis and grouped as `Unknown`.

## Data Quality Checks

The project includes basic validation steps inspired by QA work:

- checking duplicate keys
- checking missing values
- converting imported date fields
- validating product joins
- identifying missing category translations
- using `customer_unique_id` for customer-level analysis

Summary:

| Check | Result | Decision |
| --- | ---: | --- |
| Duplicate `order_id` values | `0` | Use `order_id` as the order grain. |
| Duplicate `customer_id` values | `0` | Use `customer_id` for joins. |
| Repeated `customer_unique_id` values | `3,345` | Use `customer_unique_id` for customer-level analysis. |
| Duplicate `product_id` values | `0` | Use `product_id` for product joins. |
| Unmatched product IDs in `order_items` | `0` | No product transactions are lost in joins. |
| Product categories without English translation | `2` | Group missing translations as `Unknown`. |
| Products without category | `610` | Keep transactions and group as `Unknown`. |

## How To Run

### SQL

1. Create a MySQL database named `ecommerce`.
2. Import the raw CSV files into tables with matching names.
3. Run the SQL files in this order:

```text
00_data_cleaning.sql
01_basic.sql
02_intermediate.sql
03_advanced.sql
04_KPI_metrics.sql
```

### Pandas

1. Open `pandas_analysis/01_pandas_analysis.ipynb`.
2. Run all cells from top to bottom.
3. Make sure the raw CSV files are available under `data/raw/`.

Python dependencies are listed in `requirements.txt`.

## Limitations

- Payments and reviews are not included in this version.
- Taxes, discounts, and payment behavior are not included.
- Some early and late months may contain partial data.
- The dataset is historical and does not represent current marketplace performance.
